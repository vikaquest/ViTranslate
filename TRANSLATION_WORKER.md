# Открытый модуль перевода ViTranslate

Небольшой рабочий модуль локального перевода **русский ↔ английский**.
`worker.py` — открытая версия Python-воркера ViTranslate,
с тем же протоколом и параметрами выполнения модели. Для запуска из корня изменено только определение папки моделей; алгоритм
перевода и протокол сохранены. Модуль можно изучить и запустить отдельно.

Это **открытый компонент приложения**, а не полные исходники ViTranslate.
Здесь нет интерфейса, чтения чужих полей, горячих клавиш, буфера обмена,
OCR, словарика и замены текста. По этим исходникам нельзя проверить
поведение всего EXE. Сами модели обучены сторонними авторами, а не ViTranslate.

## Быстрый запуск: Windows / PowerShell

Нужен **64-битный Python 3.12**. Инструкция проверяется на Windows x64.
При ошибке загрузки DLL CTranslate2 проверьте установленный
[Microsoft Visual C++ Redistributable x64](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist).

Скачайте репозиторий через **Code → Download ZIP**, полностью распакуйте его
и откройте PowerShell в корне распакованного репозитория, рядом с `requirements.txt`. Либо используйте Git:

```powershell
git clone https://github.com/vikaquest/ViTranslate.git
cd ViTranslate
```

Создайте отдельное окружение. Активация и изменение политики PowerShell не нужны:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe install_models.py
```

Установка зависимостей и моделей требует интернета. По умолчанию скачиваются
оба направления, **пакеты версии 1.9**. После установки перевод работает
офлайн. Распакованные пакеты занимают несколько сотен мегабайт; не удаляйте
`models/packages`. Повторный запуск установщика проверяет существующие файлы.
Чтобы установить только одно направление, добавьте `--from-code ru` или `en`.

Переведите фразу:

```powershell
.\.venv\Scripts\python.exe example.py --from-code ru "Привет, мой друг!"
.\.venv\Scripts\python.exe example.py --from-code en "I wanna play with you."
.\.venv\Scripts\python.exe example.py --from-code ru --count 3 --json "Как дела?"
```

`ru` означает **исходный русский**, результат — английский. `en` — наоборот.
Первый запуск загружает модель в память. Результат и скорость зависят
от текста, CPU и версии библиотек; разговорные выражения могут переводиться
неточно. Воркер не содержит отдельных правил для сленга и ошибочной раскладки.

## Как это устроено

```text
Текст → SentencePiece → модель Argos в CTranslate2 → SentencePiece → перевод
```

Выполнение идёт на CPU, INT8, с двумя потоками внутри запроса. Нейросетевая
модель не обучается при запуске. Длина поиска зависит от количества вариантов.
Воркер добавляет точку к фрагменту без завершающего знака — это часть текущего
поведения ViTranslate. Внешнее приложение может дополнительно ранжировать
результаты, поэтому список из GUI не обязательно полностью совпадёт с сырым
ответом этого воркера.

## Прямой протокол JSON Lines

Для постоянного процесса, который переводит много фраз без повторной загрузки:

```powershell
.\.venv\Scripts\python.exe -u worker.py --from-code en
```

Сначала stdout содержит одну строку:

```json
{"ready": true}
```

Введите запрос одной строкой и нажмите Enter:

```json
{"text": "I wanna play with you.", "count": 1}
```

Пример ответа:

```json
{"translation": "Я хочу поиграть с тобой.", "variants": ["Я хочу поиграть с тобой."]}
```

Затем можно отправлять следующие строки JSON в тот же процесс. `count` —
от 1 до 10, фактических уникальных вариантов может быть меньше. Кодировка —
UTF-8. При ошибке запуска приходит `ready: false`; при ошибке запроса —
`{"error": "имя типа ошибки"}`. Ctrl+C завершает процесс. Ошибка импорта
зависимостей выводится обычным Python traceback до объявления готовности.

## Проверка

После установки обоих направлений:

```powershell
.\.venv\Scripts\python.exe smoke_test.py
```

Проверка запускает реальные модели в обоих направлениях, варианты перевода,
UTF-8 и обработку неправильного JSON с последующим корректным запросом.
Она не управляет клавиатурой, мышью или буфером обмена.

## Состав и воспроизводимость

- `worker.py` — воркер приложения с путём к моделям рядом со скриптом.
- `requirements.txt` — фиксированные версии прямых зависимостей.
- `install_models.py` — установка официальных пакетов по `models.lock.json`.
- `models.lock.json` — версии, ссылки и SHA-256 основных файлов моделей.
- `example.py` — небольшой пример вызова из Python.
- `smoke_test.py` — проверка после установки.
- `THIRD_PARTY.md` — сторонние компоненты и сведения о моделях.

Для проверки связи с текущим исходным воркером используется файл
`SOURCE.json` с SHA-256 исходного файла и опубликованной версии. Изменение пути описано
явно; эти отпечатки не доказывают соответствие всего бинарного
приложения этим исходникам. Библиотеки и файлы моделей в Git не добавляются.
